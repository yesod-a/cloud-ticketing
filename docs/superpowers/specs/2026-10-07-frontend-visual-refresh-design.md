# Cloud Ticketing 前端视觉改造设计

## 目标

在不改变现有接口、认证流程、业务状态和测试选择器的前提下，将前端从偏后台控制台的深色表单风格，调整为更接近现场票务产品的深色体验风格。重点提升活动浏览、场次选择、选座、订单和支付链路的视觉层级与移动端可用性。

## 现有边界

- 技术栈保持 Vue 3 + TypeScript + Vite + CSS + `lucide-vue-next`。
- 保留 `App.vue` 当前的页面状态切换方式，不在本次改造中引入新的路由体系。
- 保留现有 API 调用、认证逻辑、订单状态和 `data-testid`。
- 不增加后端接口，不伪造统计数据，不把模拟支付改成真实支付。
- 用户端和管理端共用基础设计令牌，但分别维护页面级布局样式。

## 视觉方向

采用“深色现场票务平台”方向：深色舞台背景、青绿色操作主色、橙色金额与倒计时、低对比边框、大面积活动图片和清晰的信息层级。用户端强调活动封面、选座和支付转化；管理端强调数据密度、操作效率和危险状态识别。

## 页面范围

1. 全局导航、按钮、输入框、卡片、弹窗、状态标签和响应式基础样式。
2. 登录/注册页：保持双栏结构，强化品牌内容、输入状态和加载反馈。
3. 活动列表：图片主导的活动卡片、筛选区、空状态和分页。
4. 选座与通票：活动头部、场次卡片、座位图图例、订单摘要和移动端固定操作栏。
5. 订单与支付：订单卡片/响应式表格、状态标签、支付步骤感、二维码和倒计时信息层级。
6. 个人中心与管理后台：账户工作台、后台导航、表格、弹窗和场馆座位预览。

## 样式组织

优先在现有 `web/src/styles.css` 内完成视觉令牌和公共样式整理；只有在重复明显且不影响范围时，才抽取小型公共组件。第一阶段不引入 Element Plus、Ant Design 等新的 UI 框架。

建议令牌包括背景、面板、边框、正文、弱化文字、主色、警告色、危险色、圆角、阴影和间距。桌面、平板、移动端分别验证 1200px、768px、375px 附近布局。

## 验收标准

- 用户端活动封面成为列表主视觉，卡片、按钮和状态层级清晰。
- 选座后座位摘要、金额和继续支付动作在桌面和移动端都可见。
- 通票模式不展示误导性的实体座位选择界面。
- 订单和支付状态有统一中文文案与可辨识的视觉状态。
- 375px 宽度下无横向溢出，弹窗和表格可用。
- 现有前端测试和构建通过，接口、认证和测试选择器不回归。
