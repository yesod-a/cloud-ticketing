## Coverage and limits

- Auth tests cover duplicate credentials, inactive-user login rejection, validation, and response fields. JWT tests cover HMAC verification, expiration, and anonymous-route policy.
- Public activity service seeds two published activities: `星河现场 · 城市之声` and `海岸线音乐节`.
- The Compose stack was started and health-checked for the auth/RBAC verification. Kafka recovery, Nacos registration, cross-service discovery, and browser end-to-end flows were not exhaustively exercised here.
- Payment provider integration, ticket issuance, and reconciliation remain outside the verified scope. Orders, refund requests, activities, sessions, seats, inventory, users, and audit lists are database-backed; Nacos registration is verified, while dynamic route switching and full cross-service discovery failover are not.
- Consumer-side `processed_event` storage and DLQ/retry consumers are not yet implemented; the current reliability scope covers producer outbox persistence, publish retry bookkeeping, request-digest idempotency, and expiry recovery.
- The order-to-inventory reservation path is implemented and verified for lock/release; payment confirmation and ticket issuance remain outside this local scope.
- Scoped admin list filtering is enforced for Activity/Session/Venue resources and inventory seats (inventory migration v5 stores activity ownership); order/refund lists currently filter by SESSION scopes because order records do not yet duplicate activity ownership.
